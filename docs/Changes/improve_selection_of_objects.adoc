= Better Selection field for objects

== Status Quo

Currently, the selection of fields is realized via the SelectItemControl field. This item allows the user to browse for a certain element and perform a selection on that. 

We need to extent that item that it becomes much faster and userfriendly.

== Requirements

* The user shall be able to browse the item as before
* The user shall be able to select the last created and/or last selected items. (List out of 10).
* The user shall be able to search within a workspace by typing the name of that item. 
* The user can arbitrarily change between each of these modes. 

== Design decisions

* The existing control will be modified to make it available at all currently used slots.
** The existing interface of pre-selecting an item, a workspace or extent shall not be modified
** The existing interface of events upon selection shall not be modified. This means that all existing users of the control shall stay compatible.
* The control shall provide a tabular selection of the different selection modes. When the user clicks upon one of these, the page corresponding page shall show up.

The TypeScript classes will be broken up into four TypeScript classes, each representing its with self-hosting capability, so an integrator could also reuse the single components. The communication between the integrating control and its selection mechanism shall be according the similar interface. 

The names of these controls are: 

* Container: SelectItemControl (as before)
* Browsing instance: SelectItemByBrowseControl (will contain the existing logic)
* Last History instance: SelectItemByLastItemControl (will be withheld until a user session concept will be realized)
* Find by Freetext: SelectItemByFreeTextControl

=== Mode: Browsing instance

* Nothing to be specified here, we can keep the existing concept. The interfaces from the container element to that instance need to be propagated

=== Mode: Last History Instance

* Will be withheld due to insufficient infrastructure for user sessions

=== Mode: Find by Freetext

* The user has to select the Workspace itself. This is a standard Dropdown. By selecting the workspace, the search space can be reduced and higher performance can be achieved.
* The user can select the interface in which the extent is being searched. In case nothing is selected, within all extents of the given workspace will be selected
* The user can type-in a free text. Upon all elements of the selected extent(s), the name field will be evaluated. In case an element is found via the compositing properties, it will be shown as a list. The user can now click on that element to select it.
* The search is performed via the query logic. No other logic will be implemented on server side since the existing infrastructure is able to support the current need.
