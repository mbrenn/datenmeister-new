= Swimlanes

== Purpose and Usecase

We would like to generate a report out of a set of objects which collect the objects in a swimlane-based table view.

Using as an example:

* We have a set of tasks which are planned on a sprint and are assigned to a person.
* Out of that set of tasks, a table shall be created in which the sprints are ordered and shown as vertical swimlanes.
** The assigned person are shown as horizontal swimlanes.

== Requirements

* The swimlane table shall support a vertical and horizontal swimlane, each by a configurable property
* The swimlane can be shown in the webview by clicking the action button on a SwimlaneViewDefinition
* The Object and Collection view shall support a tab of a Swimlane Table as a configurable plugin. 
* The swimlane table shall exportable as a file (html)
** The rendering of the swimlane shall happen in JavaScript to support offline export
* The clustering of data in swimlane rows and columns shall be supported as a datatransformation, so other tools can
directly work on the transformed data.

=== Configuration

The Swimlane configuration describes of how to create the swimlane table. It does not contain the reference to the 
data itself, it just describes how the swimlane table shall be generated out of objects which are 'filled-in'.

The configuration data will be the following:

*SwimlaneConfiguration*

[cols="1,3", options="header"]
|===
|Property|Meaning
|verticalSwimlaneProperty|Name of the property which will be spanned up in vertical swimlanes. As in the example
above, it is the "Sprint".
|horizontalSwimlaneProperty|Name of the property which will be spanned up in horizontal swimlanes (rows). As in the example
above, it is the "Assigned To"
|cellContent|Scriban template which will be used to show the content. In case the value is not set, the standard
Name will be used
|linkContent|Boolean indicating whether a link shall be added.
|===

== Sequence Chart & Execution Flow

The following sequence diagram and description outline the end-to-end workflow from the user clicking the action button on a `SwimlaneViewDefinition` until the swimlane report is rendered in the browser.

=== Execution Description

1. **Button Click & Client Action Dispatch**:
   * The user navigates to a `SwimlaneViewDefinition` item form and clicks the action button associated with `Reports.Swimlane.Show`.
   * The client action registry routes execution to the `SwimlaneRenderAction` client module (`Assets/Js/DatenMeister.Reports.Swimlane.ts`).

2. **Temporary Action Creation**:
   * The client invokes `ClientElements.createTemporaryElement` on the server to instantiate a temporary `SwimlaneRenderAction` element.
   * It sets the `swimlaneViewDefinition` reference property of the temporary action to point to the active `SwimlaneViewDefinition` element URI.

3. **Navigation to ActionPure**:
   * The client constructs and executes a `NavigateOpenActionInWindow` client action specifying `context: "render"` and the temporary action's URI.
   * A popup window is opened displaying the `/ActionPure.html` master page.

4. **Server-Side Action Evaluation**:
   * `ActionPure.ts` initializes on page load and posts an action execution request to the server with `context: "render"`.
   * The server routes the request to `SwimLaneViewDefinitionActionHandler.cs` (`IActionHandler`).
   * The handler inspects the `SwimlaneRenderAction`, resolves the referenced `SwimlaneViewDefinition`, and creates a temporary `SwimlaneForm` object with the view definition attached.
   * The handler wraps `SwimlaneForm` inside a `RenderFormClientAction` and returns an `ActionResult`.

5. **Decoupled Form Instantiation**:
   * `ActionPure.ts` receives the `ActionResult` and executes the `RenderFormClientAction`.
   * `FormFactory` detects that `SwimlaneForm` is registered as a decoupled form (`FormFactory.registerDecoupledForm`) and instantiates `SwimlaneForm`.

6. **ViewNode Query & Data Clustering**:
   * `SwimlaneForm` loads the `SwimlaneViewDefinition`, its `SwimlaneConfiguration`, and the referenced `ViewNode`.
   * It executes `ClientElements.executeViewNode` to fetch the source items defined by the ViewNode.
   * `buildSwimlaneData` parses the items and groups them according to `verticalSwimlaneProperty` (columns) and `horizontalSwimlaneProperty` (rows) into a two-dimensional cell grid.

7. **DOM Rendering**:
   * `renderInto` dynamically generates the HTML `<table>` structure with styled column headers (`<thead>`), row titles, and table cells (`<td>`).
   * For each item in a cell, the template (`cellContent`) is evaluated (or default name fallback) and navigation links are injected when `linkContent` is enabled.
   * The rendered swimlane table is injected into the `pageContent` container on `ActionPure.html` and presented to the user.

== Implementation Reference (DatenMeister.Reports.Swimlane)

The following describes the implementation of each file located in the `DatenMeister.Reports.Swimlane` project:

=== Plugin & Backend Logic

* `Plugin.cs`:
  The entry point for the plugin implementing `IDatenMeisterPlugin` with `[PluginLoading(PluginLoadingPosition.AfterLoadingOfExtents)]`. It uses `PluginHelper` to load and register the type extent (`Xmi/Types.xmi`), the management form extent (`Xmi/Forms.xmi`), the client-side JavaScript asset (`Js/DatenMeister.Reports.Swimlane.js`), and the `SwimLaneViewDefinitionActionHandler`.
* `SwimLaneViewDefinitionActionHandler.cs`:
  The action handler implementing `IActionHandler`. It handles `SwimlaneRenderAction` and `SwimlaneViewDefinition` elements when executed with `actionVerb == "render"`. It constructs a `SwimlaneForm` instance referencing the target `SwimlaneViewDefinition` and returns an `ActionResult` containing a `RenderFormClientAction`.

=== Model & Form Definitions (XMI)

* `Xmi/Types.xmi`:
  The MOF/UML metamodel containing the class definitions for the Swimlane report:
  ** `SwimlaneConfiguration`: Defines the configuration properties (`verticalSwimlaneProperty`, `horizontalSwimlaneProperty`, `cellContent`, and `linkContent`).
  ** `SwimlaneViewDefinition`: Defines the view definition entity with a `name`, a reference to `SwimlaneConfiguration`, and a reference to the source `ViewNode`.
  ** `SwimlaneRenderAction`: Dedicated action type referencing the `SwimlaneViewDefinition` to trigger the popup rendering workflow.
  ** `SwimlaneForm`: Decoupled form specialization of `DatenMeister.Models.Forms.Form` carrying a reference to `SwimlaneViewDefinition`.
* `Xmi/Forms.xmi`:
  The form definitions for the metamodel types:
  ** Form for `SwimlaneConfiguration` providing property fields for vertical/horizontal properties, cell template, and link options.
  ** Form for `SwimlaneViewDefinition` providing fields for view definition metadata and an action button (`Reports.Swimlane.Show`) that executes `SwimlaneRenderAction`.

=== Generated Models & Wrappers

* `Model/Types.cs`:
  The generated C# classes, URI constants, and property descriptors for the types defined in `Types.xmi`.
* `Model/Types.wrapper.cs`:
  The generated C# strongly-typed wrapper classes (`SwimlaneConfiguration_Wrapper`, `SwimlaneViewDefinition_Wrapper`, `SwimlaneRenderAction_Wrapper`, and `SwimlaneForm_Wrapper`) providing typed access to underlying `IElement` properties.
* `Model/Types.ts`:
  The generated TypeScript interfaces and type constants corresponding to `Types.xmi`.
* `Assets/Js/Types.ts`:
  TypeScript namespace, URI constants, and property name constants copied from `Model/Types.ts` for client-side JavaScript usage.

=== Client-Side Implementation (TypeScript / JavaScript)

* `Assets/Js/DatenMeister.Reports.Swimlane.ts`:
  The main client-side implementation containing:
  ** `init()`: Registers the `SwimlaneRenderAction` action module under `Reports.Swimlane.Show` with `FormActions` and registers `SwimlaneForm` with `FormFactory.registerDecoupledForm`.
  ** `SwimlaneRenderAction`: Client action module (`IItemFormActionModule`) that creates a temporary `SwimlaneRenderAction` on the server referencing the current `SwimlaneViewDefinition` and executes `NavigateOpenActionInWindow` in the `render` context.
  ** `SwimlaneForm`: Decoupled form component (`IDecoupledForm`) that fetches the `SwimlaneViewDefinition`, its configuration, and the referenced `ViewNode`, queries the `ViewNode` elements via `ClientElements.executeViewNode`, clusters the items into row and column cells (`buildSwimlaneData`), and dynamically renders the HTML table into the DOM (`renderInto`) with templating and navigation links.
* `Assets/Js/Test.Swimlane.ts`:
  Client-side test and verification script for swimlane clustering and rendering logic.
* `Js/DatenMeister.Reports.Swimlane.js`:
  The compiled, bundled, and minified ECMAScript module produced by `esbuild` from `Assets/Js/DatenMeister.Reports.Swimlane.ts`, embedded as a resource in the assembly and served to the browser.
* `Js/Test.Swimlane.js` and `Js/Types.js`:
  Compiled JavaScript outputs corresponding to `Assets/Js/Test.Swimlane.ts` and `Assets/Js/Types.ts`.

=== Build & Project Configuration

* `DatenMeister.Reports.Swimlane.csproj`:
  The .NET C# project file configuring project references (`DatenMeister.Plugins`, `DatenMeister.Plugins.Helper`), target framework (`net10.0`), and embedded resources (`Types.xmi`, `Forms.xmi`, `DatenMeister.Reports.Swimlane.js`).
* `.bsmake/Build.cs` and `.bsmake/Build.csproj`:
  BurnSystems build agent script that automates copying model definitions (`Model/Types.ts` to `Assets/Js/Types.ts`), compiling TypeScript (`npx tsc`), and bundling JavaScript into `Js/` (`npx esbuild`).
* `build.cake`:
  Cake build script for building and bundling TypeScript and JavaScript assets.
* `package.json` and `tsconfig.json`:
  NPM dependencies, script definitions, and TypeScript compiler settings for the project's frontend assets.
